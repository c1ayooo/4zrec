# 小程序接口与业务逻辑测试：签名、越权、支付

## 端点提取与未授权重放

1. `miniprogram_findrefs` 搜 `wx.request`、`request(`、`https?://`、`uploadFile`、`downloadFile`，汇总 host/path 清单。
2. `http_probe` 逐个无凭据重放：小程序后端接口普遍缺少统一的鉴权中间件，裸奔接口比例高于 Web。
3. 注意 host 清单里的管理后台域名（`admin.`/`api-admin`）——小程序包常把管理端接口也打进去。

## 签名与防重放

- 统一 request 包装层的常见签名：参数按 key 排序拼接 + 固定盐/appid 派生值 + MD5/HMAC；或时间戳+nonce+sign。
- 审计点（findrefs 定位后 `miniprogram_source` 读全文）：
  - 盐/密钥硬编码在包内 → 签名算法可完全复现（node 复现脚本）
  - timestamp/nonce 是否真的服务端校验（重放同一签名多次成功 = 防重放失效）
  - 签名是否覆盖全部参数（漏 body/漏 query = 可篡改）

## 越权测试

- 横向：资源 ID（订单/地址/用户）遍历替换，`http_session` 保 A 账号登录态请求 B 资源比对响应。
- 纵向：普通用户 token 调管理接口（包内提取的管理端 path）。
- 鉴权薄弱信号：token 为纯 openid 的可逆编码；接口用 body 里的 userId 而非 token 身份做查询。

## 支付逻辑

- 金额/数量/优惠是否前端计算后上传（下单接口直接传 price）。
- 订单状态机跳步：未支付直接触发发货/核销回调；回调验签缺失可伪造支付成功通知。
- 测试纪律：最小金额自建订单；绝不篡改真实他人交易；测试结论标注订单号与金额。

## 验证码、频控与批量

- 短信/订阅消息验证码：可枚举（4-6 位无错误次数限制）、发送无频控、验证结果前端判断。
- 签到/抽奖/领券：重放批量调用；防重放字段（timestamp+nonce）形同虚设时可批量刷。
- 边界：批量验证仅在授权范围且限速执行，结果用少量样本表述。

## 账本闭环

平台扫描发现会生成测试项（接口/密钥/appid/云环境/敏感 URL 各带验证指令）：

1. `miniprogram_test_items` 拉清单（默认 pending）
2. 逐项验证（结合 findrefs/source 定位证据）
3. `miniprogram_test_item_update` 回写 confirmed/clean/na + 一句话结论 + 证据摘要
4. confirmed 项 record_vulnerability 落库（类型枚举：小程序接口未授权/小程序逻辑缺陷/小程序支付漏洞等）
