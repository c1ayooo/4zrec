# 跨平台小程序与包内容覆盖边界

平台小程序链路当前只内置微信（wx.* API、wxapkg、cloud.callFunction）。角色描述覆盖「微信/支付宝」，其他平台按本条目手动适配。

## 跨平台包结构差异

| 平台 | 包格式 | 关键特征 | API 前缀 |
| --- | --- | --- | --- |
| 微信 | wxapkg（二进制索引包） | 0xBE...0xED、V1MMWX 加密（PC 4.x） | wx.* |
| 支付宝 | .tar / .zip 归档 | 解压即源码，.axml/.acss 页面 | my.* |
| 抖音 | .tpk / zip 变体 | .ttml 页面 | tt.* |
| 百度 | .zip | .swan 页面 | swan.* |
| QQ | .zip 变体 | .qml 页面 | qq.* |

- 支付宝系（.tar/.zip）不需要 wxapkg 解析器——普通解压后按源码审计；敏感扫描正则需把 `my.request`/`my.cloud` 纳入端点提取（当前平台正则以 wx.* 为主）。
- 跨端框架产物（uni-app / Taro / mpvue 编译后）：vendor 大包 + 业务分包；runtime 含框架胶水层，审计时按编译产物形态读，源码映射（sourcemap）若随包发布可直接还原源码。

## 平台覆盖边界（当前实现）

已内置：wxapkg 解析、V1MMWX 解密、分包合并（覆盖报告）、五类敏感扫描（wx.request/uploadFile/downloadFile/fetch/cloud.callFunction 端点、密钥、appid、env、敏感 URL）、测试项账本、PC/Android 取包、登录态链工具。

未内置（发现时如实标注并手工处理）：

- 插件（plugin:// 独立包）、Worker 脚本、WASM（wxwebassembly）、开放数据域子包的自动提取
- 支付宝/抖音/百度/QQ 的包处理与 API 前缀扫描
- DevTools 协议运行时 hook（前端校验/签名/加密的动态观察仍靠静态推断 + node 复现）

## 手工兜底流程

1. 非微信包：按上表解压/解包到 `data/miniprogram_analysis/<目录>/` 同级结构（或直接以目录形式人工审）
2. 用 miniprogram_findrefs 的宿主搜索不可用时，直接 grep 解包目录（正则把对应平台 API 前缀加进去）
3. 登录态链仅微信内置；其他平台凭据（支付宝 appid+私钥等）按凭据验真工具支持范围处理，不支持则手工最小化验证
